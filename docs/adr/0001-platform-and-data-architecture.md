# ADR 0001：平台与数据架构

- 状态：Accepted
- 日期：2026-08-07

## 背景

产品需要同时覆盖 Android 手机/平板、iPhone/iPad，并保证任务提醒和知识库在离线状态仍然可用。GitHub 资讯需要定时聚合、去重和推送，不能在每台设备上重复抓取。

## 决策

1. 客户端使用 Flutter/Dart，一套代码覆盖 Android 和 iOS/iPadOS。
2. 日程和知识库采用离线优先；本地数据库使用 SQLite，优先选择 Drift。
3. 任务提醒使用设备本地通知，不依赖远程推送。
4. GitHub 资讯由 Supabase Edge Function/Cron 集中抓取，Token 只存在服务端。
5. 资讯远程推送使用 APNs/FCM；HMS 通过独立 provider 接口接入，不污染核心业务。
6. 窗口布局按可用宽度而不是设备型号响应：`<600dp` 单栏、`600-840dp` 双栏、`>840dp` 三栏能力。

## 兼容边界

- 基线暂定 Android 8+ 和 iOS/iPadOS 15+，在首次真机构建后复核。
- 不承诺绕过系统或厂商电量限制后的绝对准时提醒。
- 无 Google 服务的设备在 HMS 适配完成前只保证本地提醒，不保证远程资讯推送。
- 折叠屏按动态窗口宽度适配，不为具体型号编写分支。

## 后果

- 优点：核心数据和提醒离线可靠；手机和平板共享大部分代码；密钥不会进入客户端。
- 代价：需要解决本地/云端同步冲突；APNs、FCM、HMS 的运维和真机测试成本独立存在。

## 验证条件

- Flutter CI 能构建 Android AAB 和 iOS 测试包。
- 四类真机完成通知和深链验证。
- RLS 越权测试、双设备冲突测试和 GitHub 限流回退测试通过。
