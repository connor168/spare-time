# Focus Flow 产品需求文档

> 版本：1.0  
> 更新日期：2026-08-15  
> 状态：第一版需求已确认，待实现与验收  
> 优先级：本文件高于早期计划和历史状态报告

## 1. 产品定位

Focus Flow 是一款面向学生个人使用的 Android 时间管理与科技资讯 App。第一版围绕两个核心问题：

1. 清楚地告诉用户每天每个时间段应该做什么，并记录是否完成。
2. 每天集中提供值得关注的 GitHub 热门项目、AI、科技和 Linux/开源资讯，减少用户自行搜索和筛选的时间。

第一阶段只供项目作者个人使用，但数据模型和账号体系需要支持同一用户在多台 Android 设备间同步。

## 2. 第一版边界

### 2.1 目标平台

- 第一版只承诺 Android。
- iOS、iPadOS、Windows 和公开应用商店发布不属于本轮验收范围。
- 现有跨平台代码可以保留，但不得因维护其他平台阻塞 Android 核心闭环。

### 2.2 非目标

- 不使用 AI 模型或云端 AI API 自动规划时间。
- 不把未完成任务自动延续到第二天。
- 不在第一版开发通用的课程表截图、Excel、教务系统或日历文件导入 UI。
- 不连续发送约 50 条新闻通知；每天只发送一条资讯更新通知。
- 不在客户端中保存 GitHub、微信、QQ 或其他服务的私密密钥。

## 3. 用户基础作息

当前默认作息用于日程展示和本地规则排程：

| 时间 | 默认安排 |
| --- | --- |
| 06:30 | 起床并与团队伙伴开始训练 |
| 07:20 | 训练结束，随后早餐 |
| 白天 | 根据导入的课程表上课；课程外的中午和下午时间可安排学习 |
| 晚上 | 无课时安排个人学习和其他目标 |
| 23:00 | 睡觉，之后不再自动安排任务 |

课程的准确起止时间、教学周和日期以用户后续提供的真实学期课表为准。默认作息必须可在设置中修改，不能永久硬编码为不可变数据。

## 4. 日程与时间管理需求

### 4.1 课程表

- 用户后续提供每周课程表的真实样例。
- 第一版把课程表作为一次性数据导入任务：直接解析用户文件并写入 App 可读取的数据，不开发通用导入入口。
- 导入后，用户能够按日期看到当天每门课的名称、开始时间和结束时间。
- 课程时间视为已占用时间，自动排程不得与之冲突。
- 如输入材料包含教学周、单双周或临时调课信息，导入数据必须保留并正确应用；输入材料没有的信息不得猜测。

### 4.2 手动计划

- 用户可以手动创建、编辑、拖动和删除时间块。
- 时间块至少包含标题、日期、开始时间、结束时间、状态和提醒设置。
- 作业、考试准备和个人目标可以拆分成当天的学习时间块。
- 用户可以将时间块标记为已完成或今日未完成。

### 4.3 本地规则计划草稿

- 输入来源包括课程表、作业、考试日期和个人目标。
- 排程仅使用本地可解释规则，不调用 AI 模型或 AI API。
- 规则只能使用当天课程和固定作息之外的空闲区间，不得产生时间冲突，也不得越过 23:00。
- 每个学习任务的实际时长由用户在草稿中决定或修改；系统不能未经确认擅自固定最终时长。
- 自动生成结果必须先进入“计划草稿”，不得直接写入正式日程。
- 草稿界面必须允许用户拖动、调整起止时间、增删任务；只有用户明确确认后才生效。

### 4.4 未完成任务处理

- 当学习任务未完成时，App 可以在当天剩余的空闲时间中建议或执行重排。
- 重排不得占用课程、训练、用餐、已有任务或睡眠时间。
- 重排后的时间仍须在当天，绝不自动移动到第二天。
- 当天没有足够空位时，任务标记为“今日未完成”。
- 今日未完成记录必须保留在历史和统计中，由用户之后手动决定如何处理。

### 4.5 提醒与完成记录

- 课程和普通时间块默认在开始前 5 分钟发送本地提醒。
- 用户可以修改或关闭单个时间块的提醒。
- 通知应显示任务/课程名称和开始时间；点击后进入对应详情。
- App 必须保存已完成、今日未完成等状态，用于当天回顾和历史查询。
- 设备重启或 App 被关闭后，未来的本地提醒仍应按 Android 能力恢复；受厂商省电策略影响时应向用户说明。

## 5. 科技资讯需求

### 5.1 内容范围与来源

- GitHub 热门开源项目：通过 GitHub API 获取。
- AI 新闻与项目动态：通过可靠 RSS、新闻站点以及相关 GitHub 数据获取。
- 综合科技新闻：通过可靠 RSS 和新闻站点获取。
- Linux/开源新闻：通过可靠 RSS、新闻站点以及相关 GitHub 数据获取。
- 每条资讯必须保存来源名称、原文标题、发布时间（来源提供时）、原文链接和抓取时间。
- 聚合需要去重；来源失败时应保留最近一次成功缓存并显示数据可能已过期。

第一版每天目标约 50 条，初始配额建议如下，后续可根据实际阅读体验调整：

| 分类 | 建议数量 |
| --- | ---: |
| GitHub 热门项目 | 15 |
| AI 新闻与动态 | 15 |
| 综合科技新闻 | 10 |
| Linux/开源新闻 | 10 |

### 5.2 每日更新通知

- 每天按用户本地时间 07:00 更新资讯。
- 每天只发送一条“今日资讯已更新”通知，不为每篇内容分别通知。
- 点击通知进入当天资讯列表。
- 约 50 条是 App 内当天内容数量目标，不是通知数量。
- 网络失败时不得发送误导性的“已更新”通知；可继续展示最近成功内容并标记更新时间。

### 5.3 中英文显示

- 英文内容必须保留原文。
- 用户可以在原文和中文翻译之间切换；适合时可以同时查看中英文。
- 中文翻译优先使用 Android 设备上的本地翻译能力，不依赖付费云端翻译 API。
- 本地翻译不可用或失败时，显示英文原文和明确状态，不伪造翻译结果。
- 翻译结果应本地缓存，避免重复处理。
- 无论使用哪种语言显示，都必须保留来源名称和可打开的原文链接。

## 6. 账号与多设备同步

- 第一版必须支持登录，并允许同一账号在多台 Android 设备同步课程、计划、任务状态、历史记录和必要设置。
- 第一版目标登录方式为微信登录和 QQ 登录。
- 同步应采用离线优先策略：无网络时仍能查看和编辑本地日程，恢复网络后同步。
- 同步不得产生重复任务、静默丢失删除记录或泄露其他账号数据。
- 双设备同时修改产生冲突时，必须向用户展示可理解的处理结果，不能直接覆盖且不提示。

### 6.1 微信/QQ 登录外部前置条件

真实登录联调前，项目所有者需要完成以下工作：

1. 注册并完成微信开放平台、QQ 互联要求的开发者认证。
2. 分别创建 Android 移动应用并提交平台审核。
3. 使用已确认的永久 Android 包名 `com.focusflow.planner`；后续不得为不同平台配置随意更换包名。
4. 创建 Android 发布 keystore，妥善备份 keystore、alias 和密码，并取得平台要求的签名证书指纹。
5. 在开放平台配置正式包名、签名信息和服务端回调地址。
6. 将 App ID 等公开客户端配置放入环境配置；App Secret 等密钥只能保存在安全的服务端 secrets 中，不得写入源码或提交到 Git。

微信/QQ 平台的应用资质、审核和凭据由项目所有者申请；项目代码负责 SDK 接入、服务端换取会话、错误处理、账号绑定和真实设备联调。缺少平台批准或凭据时，该功能只能完成代码骨架，不能标记为验收通过。

## 7. 数据与隐私要求

- 本地至少保存课程、时间块、提醒、完成状态、历史记录、资讯缓存和翻译缓存。
- 云端只同步实现多设备体验所需的数据。
- 开放平台密钥和 GitHub 私密 Token 不得进入客户端、日志或版本库。
- 用户应能退出登录；退出后不得继续显示其他账号的私有日程。
- 后续公开发布前必须补充隐私政策、数据导出和账号删除流程；个人内测阶段仍应遵守最小化收集原则。

## 8. 第一版关键验收场景

1. 用户能查看由真实课程表导入生成的某一天课程时间段。
2. 用户能手动创建任务，并在开始前 5 分钟收到提醒。
3. App 能根据当天课程和空闲区间生成本地计划草稿；用户拖动修改并确认后才进入正式日程。
4. 未完成任务可在当天有空位时重排；无空位时成为今日未完成并出现在历史中，第二天不会自动出现副本。
5. 每天 07:00 只收到一条资讯更新通知，点击后能查看约 50 条分类内容。
6. 资讯能在英文原文与设备本地中文翻译间切换，且每条都能打开原始来源。
7. 微信和 QQ 能在真实 Android 设备完成授权、回调和登录；缺少平台资质或审核时不得跳过此项并宣称完成。
8. 同一账号在两台 Android 设备上能同步计划和完成状态，断网编辑后恢复网络能达到一致状态。
9. 当前提交通过静态分析、全量自动化测试、Android 构建及核心流程真机验收后，第一版才可标记完成。

## 9. 推荐实施顺序

1. 修复当前工程，使 Android 项目恢复可分析、可测试、可构建状态。
2. 完成课程/任务时间轴、状态历史、本地提醒闭环。
3. 完成本地规则草稿、拖动修改、确认生效和当日重排。
4. 在用户提供课表后执行一次性解析与数据导入。
5. 完成 GitHub API、RSS/新闻源聚合、去重缓存、约 50 条列表和每日单条通知。
6. 接入设备本地翻译并完成双语切换和缓存。
7. 确认包名和发布签名；等待微信/QQ资质期间完成 SDK 与服务端接入骨架。
8. 获得平台凭据后完成微信/QQ真实登录、多设备同步与 Android 真机验收。

- 真实学期课程表样例及其教学周、单双周等必要说明。

- Android 发布签名的创建与安全备份。
- 微信开放平台开发者认证、移动应用审核和凭据。
- QQ 互联开发者认证、移动应用审核和凭据。
