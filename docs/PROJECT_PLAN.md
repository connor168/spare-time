# 时间管理与 AI 技术资讯 App 实施计划

> 版本：0.7（阶段 0 完成，阶段 1/2/5 基础代码已落地）  
> 更新日期：2026-08-07  
> 状态：Flutter 基线已采用；等待 Flutter SDK 后完成构建验证

## 1. 产品目标

为希望紧凑安排时间的用户提供一款 Android/iOS 跨平台应用，覆盖手机、平板、横竖屏、iPad 分屏和部分折叠屏设备：

1. 快速创建每日任务和日程。
2. 在指定时间通过本地通知提醒用户，即使离线也能工作。
3. 每天聚合 GitHub 上与 AI/科技相关的热门项目动态，并按用户兴趣推送。
4. 提供可离线使用的个人知识库，用于记录心得并搜索、导出。

### 非目标（MVP 不做）

- 承诺覆盖“所有手机”或所有厂商的后台行为。
- 抓取全网新闻或直接抓取不稳定的 GitHub Trending 页面。
- 多人协作、社交、知识图谱、复杂 AI 自动规划。
- 把 GitHub 私密 Token 或摘要服务密钥放入客户端。

## 2. 产品边界与技术基线

### 已建议的基线

- 移动端：Flutter/Dart。
- 本地数据：SQLite（优先评估 Drift）。
- 云端：Supabase Auth、Postgres、Edge Functions、Cron。
- 任务提醒：本地通知；资讯推送：FCM/APNs，HMS 作为单独适配项。
- 笔记格式：Markdown 或纯文本，支持导出。
- 支持范围：Android 8+、iOS/iPadOS 15+；具体最低版本在阶段 0 决定。
- 数据策略：日程和知识库离线优先；GitHub 资讯由后端集中抓取。
- 账户策略：默认允许游客本地使用，登录后才开启跨设备同步。
- 默认资讯策略：用户本地时间 08:00 推送，最多 10 条，可在设置中修改。
- 华为 MVP：支持本地数据与本地提醒；HMS 完成前不承诺远程资讯推送。

### 阶段 0 已完成的决策

- 支持游客本地模式；登录后通过一次性迁移流程启用云同步。
- 任务保存 IANA 时区 ID；时区、系统时间和夏令时逻辑必须由测试固定。
- 华为无 Google 服务设备的本地功能属于 MVP，HMS 远程推送属于后续兼容项。
- MVP 附件单文件上限暂定 10MB；用户必须能够导出和删除个人数据。
- GitHub 热点评分和摘要条数可配置，默认每天最多 10 条。

## 3. 目标用户流程

### 日程

打开 App -> 查看今日时间轴 -> 添加任务 -> 设置开始/结束时间和提前提醒 -> 本地通知 -> 点击通知打开任务 -> 标记完成。

### AI 资讯

后端定时抓取 -> 按主题和热度评分 -> 去重并缓存 -> 生成摘要（失败则使用原始描述） -> 按用户时区发送每日摘要 -> 点击进入 GitHub 原始链接。

### 知识库

新建笔记 -> 自动保存到本地 -> 添加标签/收藏 -> 全文搜索 -> 可选关联资讯 -> 导出备份。

## 4. 功能规格与验收标准

### F1 日程与任务

- 今日列表、日历视图、时间轴视图。
- 创建、编辑、删除、完成、逾期状态。
- 开始时间、结束时间、优先级、备注、重复规则。
- 提前提醒：至少支持 0、5、15、30 分钟。
- 跨天任务和重复任务必须有明确展示。

**验收：** 断网、锁屏、杀掉 App、重启设备后任务仍存在；通知点击能打开正确任务；重复任务在时区变化和夏令时边界不发生错时。

### F2 本地通知

- Android 13+ 和 iOS 通知权限拒绝时提供可恢复引导。
- Android 精确闹钟、Doze、电量优化影响要有说明和降级策略。
- 设备重启后重新注册未来提醒。
- 通知包含任务标题、时间和深链。

**验收：** 在至少一台 Android 手机、一台 Android 平板、一台 iPhone 和一台 iPad 真机验证；目标误差为 1 分钟以内，但不对系统级省电限制作绝对准时承诺。

### F3 响应式手机/平板界面

- 小于 600dp：单栏 + 底部导航。
- 600-840dp：导航栏 + 主内容双栏。
- 大于 840dp：日历/任务时间轴/详情三栏。
- 支持横竖屏、iPad Split View、Android 多窗口、折叠屏展开/收起。
- 支持触控；键盘、鼠标和手写笔作为增强能力。

**验收：** 所有目标断点无横向溢出、重叠和布局抖动；旋转或分屏后当前页面、编辑内容和滚动位置按预期保留；字号放大后仍可操作。

### F4 个人知识库

- Markdown/纯文本编辑、自动保存、标签、收藏、全文搜索（SQLite FTS）。
- 离线新建和编辑；支持 Markdown 导出和本地备份。
- 附件需要大小、类型、删除和备份策略。

**验收：** 异常退出或重启不丢已保存内容；离线搜索可用；导出文件可重新读取；达到附件限制时有明确错误状态。

### F5 账户与同步

- Supabase Auth；Postgres 行级安全策略（RLS）。
- 本地变更队列/outbox、幂等重试、软删除 tombstone。
- 首次同步、增量同步、登出清理和多设备同步状态。
- 初版冲突策略采用字段级 last-write-wins，并向用户显示冲突结果。

**验收：** 断网期间连续编辑，恢复网络后最终一致；重复提交不产生副本；用户无法读取其他用户数据；同步失败可重试且有日志。

### F6 GitHub AI 资讯

- 仅从 GitHub 官方 REST/GraphQL API 获取数据。
- 主题：`artificial-intelligence`、`llm`、`generative-ai`、`agent` 等，可配置。
- 结合最近更新时间、Star、Fork、Star 增长、Release 事件评分。
- 规范化仓库 URL、去重、分页、缓存、ETag、429 退避。
- 保存原始描述、来源链接、抓取时间和摘要版本。

**验收：** 定时任务可安全重复执行；API 失败/限流时保留最近成功数据并显示状态；同一仓库不产生重复资讯；每条内容可回链 GitHub；Token 不进入客户端或日志。

### F7 每日推送

- 用户选择主题、推送时间、时区、安静时段和每日上限。
- FCM/APNs Token 注册、刷新、失效清理和深链。
- 摘要服务可插拔；摘要失败时显示原始项目描述。
- HMS 推送必须单独标注支持范围和测试结果。

**验收：** 按用户时区发送且幂等；点击通知进入对应资讯；关闭权限后没有死循环重试；失效 Token 被清理。

## 5. 数据模型草案

```text
Task(id, title, description, start_at, end_at, timezone, repeat_rule,
     reminder_minutes, status, priority, created_at, updated_at, deleted_at)
Note(id, title, body_markdown, tags, is_favorite, created_at, updated_at, deleted_at)
NewsItem(id, repo_full_name, title, summary, source_url, tags, stars, forks,
         published_at, fetched_at, summary_version)
UserPreference(user_id, timezone, topics, digest_time, quiet_hours, push_enabled)
DeviceToken(id, user_id, platform, token, provider, last_seen_at, invalid_at)
SyncChange(id, user_id, entity, entity_id, operation, version, created_at)
```

所有同步实体需要版本号或更新时间；删除不能立即物理删除，直到同步窗口确认完成。

## 6. 里程碑与交付物

每个阶段必须依次完成：设计 -> 实现 -> 验证 -> 文档，取得验收证据后才能进入下一阶段。

### 阶段 0：规格与技术基线

- 产出：用户故事、设备矩阵、数据模型、API 契约、通知策略、隐私边界和 ADR。
- 验证：逐条需求映射到功能、数据、测试和验收标准。

### 阶段 1：工程骨架与响应式 UI

- 产出：Flutter 工程、主题、导航、断点布局、环境变量、静态检查和 CI。
- 验证：手机/平板横竖屏和分屏截图回归，无溢出或重叠。

### 阶段 2：本地日程与通知

- 产出：SQLite schema、任务 CRUD、重复规则、提醒调度、重启恢复。
- 验证：单元测试 + 真机锁屏/杀进程/重启/改时区测试。

### 阶段 3：离线知识库

- 产出：编辑器、自动保存、标签、FTS 搜索、导出和备份。
- 验证：异常退出、离线操作、附件限制和导出回读测试。

### 阶段 4：账户与云同步

- 产出：Auth、RLS、outbox、增量同步、冲突和迁移策略。
- 验证：双设备并发编辑、断网重试、重复请求幂等和越权测试。

### 阶段 5：GitHub 聚合后端

- 产出：Cron/Edge Function、抓取器、评分、去重、缓存、限流和失败回退。
- 验证：API fixture/契约测试、重复运行、429、空结果和旧数据回退。

### 阶段 6：摘要推送与发布

- 产出：用户偏好、摘要、FCM/APNs/HMS 适配边界、深链、崩溃监控、隐私政策和商店包。
- 验证：Android 手机/平板、iPhone/iPad 真机，TestFlight/Play 内测和可回滚构建。

## 7. 质量门槛

- 单元测试：时间计算、重复规则、热点评分、去重、冲突合并。
- Widget/UI 测试：断点布局、权限状态、空态、错误态和加载态。
- 集成测试：数据库迁移、通知调度、API 契约、推送深链。
- E2E 测试：离线、弱网、锁屏、杀进程、重启、时区变化、分屏和旋转。
- 运行静态分析、格式检查、CI 构建和数据库迁移检查。
- 发布前无 P0/P1 缺陷；记录测试报告、截图、日志和已知限制。

## 8. 风险与降级

- 厂商省电策略可能延迟通知：提供系统设置引导，并保留 App 内逾期状态。
- FCM 在无 Google 服务设备不可用：HMS 单独适配或明确暂不支持远程推送。
- GitHub API 限流或字段变化：缓存最近成功结果、指数退避、监控配额。
- AI 摘要成本或内容错误：可关闭摘要，显示原始描述并保留来源链接。
- 同步冲突：显示冲突状态，不静默丢弃用户数据。
- 附件和备份产生费用：限制大小和类型，阶段 0 固定预算。
- GitHub 使用条款和内容归属：只保存必要元数据，保留原始链接和来源说明。

## 9. 计划自检与变更规则

每个里程碑结束时检查：

- 是否仍然覆盖四个核心需求和手机/平板设备矩阵。
- 每个目标是否都有可执行的测试和验收证据。
- 外部服务失败、限流、权限拒绝和离线状态是否有降级方案。
- 是否引入了不属于 MVP 的复杂功能。
- 是否新增了隐私、成本、迁移或商店审核风险。

本文件每次变更必须更新版本、日期、变更原因和未决问题。任何新需求先进入“非目标/待确认事项”评估，避免直接打乱当前里程碑。
